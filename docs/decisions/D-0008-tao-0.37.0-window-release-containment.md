# D-0008 — tao 0.37.0 window release containment (C-04)

**Status:** ACCEPTED by the owner for M1. A narrow, version-scoped exception to SPEC §18.2. It expires when tao, Tauri or Wry moves off the set below.
**Affects:** SPEC §18.1, §18.2, §18.5; D-0006 (C-04); MILESTONES M1.

## Defect

tao 0.37.0's `create_window` (`src/platform_impl/macos/window.rs`, lines 246–255) sends `alloc` and `initWithContentRect:…` into a raw pointer, which is +1 and owned by nobody. It then wraps that pointer with `Retained::retain`, a second +1 owned by tao. tao releases only its own reference, and `setReleasedWhenClosed(false)` stops AppKit from releasing the other, so a closed window is never deallocated and its window-server window stays as an off-screen shell. tao 0.37.1 and the upstream `dev` branch (read 2026-10-08) have the same lines.

Evidence, all in `evidence/M1/c04/`:

- **Baseline** (`20261007T231508Z-baseline`): 20 recoveries; shells 9 → 29, exactly +1 per recovery; UI footprint +0.57 MB per recovery.
- **Diagnostic** (`20261007T233730Z-diagnostic`): every retired window was still alive with exactly one reference left once tao, Tauri and Wry had let go. Its delegate and WKWebView were gone.
- **Experiment** (`20261007T234229Z-experiment-release`, reverted): one `release` at that point deallocated each window and its content view.
- **Ownership-neutral repairs**: `oneShot` on close (`20261008T000018Z-oneshot-on-close`) and `oneShot` with `orderOut:` (`20261008T000903Z-oneshot-order-out`) left every shell.

## Decision

Recovery sets `releasedWhenClosed = YES` on the retiring office `NSWindow` immediately before its existing destruction path (`apps/desktop/src-tauri/src/window.rs`, `release_window_on_close`), so AppKit's own close consumes the reference nobody owns. Applied to that window only. Every other window, live office windows included, keeps AppKit's and tao's defaults. The pointer is borrowed through `with_webview` for one main-thread call and never retained or released by Threadspace.

This is containment of one dependency defect, not Threadspace's window-lifetime architecture. Borrowed macOS pointers stay unowned everywhere else (SPEC §18.2).

## Safeguards

1. **Version guard.** `window::tests::window_dependencies_are_the_ones_d0008_qualified` fails the build unless `Cargo.lock` resolves exactly tao `0.37.0`, Wry `0.57.0`, Tauri `3.0.0-alpha.4` and tauri-runtime-wry `3.0.0-alpha.4`.
2. **Behavioral guard.** The view-recovery runner (`threadspace-m0c view-recovery`) is the permanent C-04 regression. Its summary passes only if, across repeated view retirement and recreation:
   - `nativeWindowShells.after == nativeWindowShells.before` after quiescence;
   - WebContent processes do not grow, and the UI footprint shows no sustained growth: its least-squares slope across the second half of the recoveries is at most 0.1 MiB per recovery. A leak costs every recovery alike (before the repair: 0.57 MiB per recovery in the second half), while a one-time cost early in a run does not count;
   - the office window keeps its bounds (within 3 pt) and stays on screen;
   - the durable intent backlog is unchanged;
   - each recreated view hydrates with an equal projection;
   - in the recreated view, the IPC suite's stale-epoch, stale-context and retired-subscription cases pass, and the first retired view's subscription is refused.
3. **Removal first on any update.** Updating Tauri, tao or Wry starts by removing `release_window_on_close` and running the view-recovery gate on the new dependency without it. If shells stay flat, the containment is gone for good. If they grow, a new decision replaces this one. Restoring it is never automatic. An upstream ownership fix would turn the call into a double release, which crashes.
4. **Marked in code.** The call and the function carry a D-0008/C-04 banner naming the double-release risk and the removal rule.

## Consequences

- C-04 closes on the M1 build (`73636ec`): `evidence/M1/view-recovery/20261008T015231Z-prod` passes every guard above over 60 recoveries; `evidence/M1/c04/NOTE.md` records the runs before it.
- SPEC §18.2 names this exception; it lapses with the pin. Nothing else may set `releasedWhenClosed` or otherwise treat a borrowed window pointer as owned.
