# D-0014 — Native Claude activation transitions

**Status:** PROPOSED
**Affects:** SPEC §4.2, §4.3, §4.9, §4.14, §4.15; D-0007 §7; M3 source slice 1.

Conventional hooks and the qualified observer establish logical openings before the inventory poll. Inventory still supplies process/surface proofs and its existing exact execution ends. Source epochs describe observation coverage, not execution lifetime.

## Representation

Keep the existing `ExecutionAttached`, `ExecutionEnded`, `TurnStarted` and `NativeExecutionRef::Activation` vocabulary. Add optional `NativeRefs.activation` metadata: evidence kind, frozen observer generation, callback entry sequence and native start source. Missing metadata reads as the existing journal representation. The JSON schemas gain optional fields and their referenced definitions; the schema and fact-payload versions remain unchanged. The reducer version is 5. Version-4 checkpoint JSON needs no rewrite; missing activation maps default empty. Older readers refuse the newer reducer checkpoint through the read-only preflight in D-0007 §6. The new producer's evidence is additive, and old facts retain their interpretation. Empty activation bookkeeping is not populated while replaying legacy-only facts. Checkpoint integrity continues to check the original stored JSON bytes before deserialization. Replay reads stored facts, without re-normalizing stored envelopes. Absent `NativeRefs.activation` is omitted when serializing, preserving legacy fact bytes.

`CanonicalState.activationCandidates` retains uncombined execution evidence; `activationFacts` retains start/end/turn evidence by observation ID and fact index. `executionAliases` is derived. Original binding executions and binding records are retained separately so an alias can converge without losing its surface proof. Admission assignments remain immutable. Only representative executions and pending inventory rows needed by retained bindings appear in the execution projection; pending rows have UNKNOWN presence. References and materialized rows move together in the same transaction. Inventory records, including ended records, recover their attach evidence from the existing record, not from a rewritten journal fact. Derived indexes key activation evidence by (process, session). Only touched runtimes are re-derived; a normal turn start reads that runtime's opening/end evidence and its own turn evidence. Alias DELETEs address only changed IDs. Ended-runtime facts remain in checkpoints because delayed openings, ends and turn callbacks can still change matching; no retained-source watermark proves that evidence complete.

## Matching and order

- A conventional principal `SessionStart` with source `startup`, `resume` or `clear`, plus a kernel provider ProcessKey and executable, establishes an opening. A qualified engine-stamped observer `classic.SessionStart` or settled engine `session.start` establishes one with its frozen generation. The adapter names the observer opening by epoch, generation and callback entry, not callback result; the relay envelope carries no added activation reference. Conventional-hook normalization selects the nearest validated Ancestor whose kernel executable has the Claude versions-directory layout. A nested Claude process takes precedence over its outer Claude ancestor; without a validated Claude ancestor, the hook establishes no activation. Stored hook bytes are unchanged.
- Repeated delivery of one opening uses the same native reference. `session.start` can corroborate the unique classic opening in the same generation. A unique conventional opening can corroborate the unique observer opening with the same ProcessKey, native session and start source, or a unique engine-only `session.start` with no start source. An engine-only corroboration is not evidence of another opening for the legacy-end rule. Repeated indistinguishable conventional reports remain raw unmatched evidence rather than being paired by timestamp.
- Within an observer epoch, the original entry sequence orders openings and scopes turns and ends. Native `startup` precedes a subsequent `resume` or `clear` in the same runtime. A later proven opening ends its predecessor. Explicit predecessor-epoch relations carry order through reloads. Receipt order, independent command-hook counters and wall-clock timestamps establish no native order.
- An inventory join merges only when its unended candidate has one matching opening and no exact end of that opening causally precedes the join. An ended inventory candidate remains its own ended group. Reconcile ends and joins carry the inventory pass point, so a later positive join can establish a separate live attachment after a lagging switch row ended the native ID; the ended ID stays ended. With several possible native openings a join remains pending evidence, including its binding row marked PENDING_ACTIVATION; it creates no extra live attachment. The next normal reconciliation can prove a surface for the exact live native execution through its existing `Surface` change. An inventory-only opening remains supported. Inventory absence remains inert.
- An observer end matches the newest opening before its original entry in its frozen process/session/generation. A legacy end can identify an initial startup only while that process/session has no evidence of another opening. A resumed or inventory-only opening cannot be closed by an otherwise unmatched legacy end. Unmatched ends remain in `activationFacts`. Host-read claims require the existing independent proof and seal.
- A verified `TurnStarted` binds to the matching opening at its original entry. Its result can arrive after another opening. Completion names the native turn and never supplies a new execution owner. A reload's proven host-read turn may inherit an opening through explicit predecessor-epoch evidence; a bare new epoch or host read creates no execution.
- Compaction and bootstrap/reload link reports create no opening. Reopening the same native session in the same generation still creates distinct records when separate opening callbacks prove it.
