## Proven cause of each original failure

The duplicate-registration hypothesis is rejected. An allowed `$.tool.call` produces the exact sequence `tool.call entry → tool.check entry → tool.check result → tool.call result`, all in **one source epoch**. The mocked bottom receives **one check and one call**. With the observer removed, the same check-before-call order and permission behavior remain. Loading debug records show one observer module load and one `plugin.register` admission.

An `ask` preflight with no simulated permission approval returns a denial **before the mocked tool bottom**. Switching only that synthetic preflight to `allow` reaches the mock and returns its unchanged result. No actual Read/file operation is used. The separate trace probe, with and without the observer, proves that the newer kit wraps its mocked tool bottom in an `engine/core` terminal link; generic mocked `prompt.submit` still terminates at `test/builtin`.

Classifications: **(a)** test-kit/environment behavior; **(b)** obsolete fixture assumption; **(c)** production observer semantics. No production defect (c) was demonstrated.
