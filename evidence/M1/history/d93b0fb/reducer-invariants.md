# M1 reducer invariant catalog

Each invariant names the rule that enforces it and the checks that exercise it. "Monitor" is the per-step invariant monitor in `tests/synthetic/src/runner.rs`, which runs after **every delivered step** of every scenario run, every permutation (10,400) and every SQLite cross-check (1,040, stepwise). "Catalog" is `tests/synthetic/src/scenarios.rs`; "SQLite tests" is `tests/synthetic/tests/sqlite.rs`.

| ID | Invariant | Enforced by | Checked by |
| --- | --- | --- | --- |
| INV-01 | One namespace + native session ID resolves to one canonical Session | Native key `["session", namespace, native]` in `state-engine/src/keys.rs`; one assignment per key (`identity_assignments` primary key); `sessions UNIQUE(namespace_id, native_session_id)` | Monitor (duplicate session check); `duplicate-deliveries` (10 deliveries each → 1 session); SQLite test `ten_deliveries_…` (3 entries, 3 facts, 1 session) |
| INV-02 | Sessions sharing cwd/repository never merge | Keys contain no cwd, repository, title or recency | `routing-ambiguity`, journal `three_same_cwd_sessions_…` |
| INV-03 | PID alone, a TTY path or a tab ordinal is never identity | ProcessKey includes boot and kernel birth; SourceSurface key includes app generation and surface generation; bindings keyed by (execution, surface) | `pid-tty-reuse` (2 processes, 2 surfaces, 1 valid binding); journal `same_pid_with_a_new_birth_…`, `a_reused_tty_path_…` |
| INV-04 | Process reuse or executable replacement invalidates old proof | ENDED is sticky; binding validity derived from execution presence, the current image (`current_image`) and whether the proven image is causally followed by another (`followed_by_another`, monotone) | `pid-tty-reuse`, `executable-replaced`, `replaced-then-unordered-image`, `executable-requalified`; Monitor (lost binding never valid again) |
| INV-05 | Resume keeps the worker; a new identity does not inherit it | Same native key → same Session; activations keyed separately | `resume` (one Session, A1 ENDED, A2 LIVE) |
| INV-06 | Identity, turn state, presence and observation stay separate | Distinct record fields, each derived from its own evidence | All catalog expectations; `dropped-observation` (presence stays UNKNOWN) |
| INV-07 | Stop/response boundary never ends execution or certifies an outcome | `ResponseBoundaryObserved` changes nothing; Claude classic Stop maps only to it | Monitor (Stop or turn.complete may never move an execution to ENDED); `normal-session`; `provider-claude::hooks` tests |
| INV-08 | A terminal outcome closes its turn; stale activity cannot regress it | Turn state = terminal if any outcome, before waits/steps/activity (`derive_turn`) | Monitor (terminal turn never non-terminal); `parallel-tools` (late tool after COMPLETED); `a-b-a-delayed` |
| INV-09 | Missing parent metadata never promotes a child | Principal only for the principal native ref; promotion refused (`ACTOR_PROMOTION_REFUSED`) | `child-actors` |
| INV-11 | Source epochs, callback sequences, ingest cursors, activations, native turn IDs and canonical IDs are separate namespaces | Separate key prefixes; causal comparison only within source/epoch/domain; ingest cursor never used as order; native turn IDs scoped to their actor in the key and in `turns UNIQUE(session_id, actor_id, native_turn_id)` | SQLite test `ingest_cursor_gaps_…` (1,000-position cursor hole raises nothing; source gap scoped to its epoch); `shared-native-turn-id` (principal and subagent `t1`, through SQLite); `state-engine` causal tests |
| INV-12 | Late callbacks keep their original identity | Facts carry their own native refs; no "current session" lookup exists | `a-b-a-delayed` (delayed completion settles tA1, not tA2) |
| INV-13 | Duplicate observations and retried owner commands are idempotent | Dedup by observation UUID (content-compared, canonical lowercase form only); commands by ID + payload fingerprint, retry returns the recorded receipt; a command that changes nothing reports the item's unchanged revision | `duplicate-deliveries`; `owner-commands`; SQLite `a_committed_owner_command_retried_…` (after revision advance and restart), `a_command_that_changes_nothing_…`, `an_observation_id_not_in_canonical_form_…`; crash matrix second retry |
| INV-14 | Valid permutations converge | Evidence-set reduction (D-0007 §1) | 10,400 seeded permutations (8 required families + duplicates/robustness), 0 failures; negative controls in `tests/synthetic/tests/scenarios.rs` |
| INV-15 | A revisionless snapshot is an interval; absence is not deletion | Snapshot kept by causal order; `present=false` only changes presence | `stale-snapshot`; journal `sessions_leaving_the_inventory_…` |
| INV-16 | Coverage claims only what was inspected | Coverage gaps recorded per source epoch; no repair invented | `dropped-observation` |
| INV-22 | Acknowledged and resolved are distinct and both survive rebuild | Separate sets; owner resolution never removed | `owner-commands`; Monitor (acknowledgement and owner resolution never lost); replay digests |
| INV-23 | Auto-resolution needs accepted, causally later human input | Frontier per (session, actor, source, epoch, domain); only with `automaticHumanFollowupResolution` | `followup-witnessed` (t1 resolved; p3 queued-before-output, p4 upstream-delayed, p5 scheduled do not resolve t2) |
| D-0005 | Claude 2.1.291: no automatic follow-up resolution; Mark handled required | `profiles::CLAUDE_NATIVE_OBSERVER` | `followup-claude` (provenance recorded, not resolved; owner Resolve resolves) |
| INV-24 | Parent-owned child output does not create owner attention | `owner_facing` fixed from the turn's native actor at creation | `child-actors` (one item: the principal's) |
| INV-25 | Unknown/unproven data never drives lifecycle | Unknown discriminators fail to deserialize; unknown events/adapters drive nothing; unresolved drafts are diagnostics | `unknown-and-malformed`; contracts `unknown_fact_discriminators_…`; hook adapter tests |
| INV-26 | Capture fails open, never waits for the renderer | Hook exits 0 silently on every path, watchdog at 250 ms; `mod-batch` flushes its typed receipt before exit; a record the store refuses is isolated and quarantined, never stalling the drain | `evidence/M1/capture/summary.json` (all failure paths); relay `mod_batch` test; companion `spool_drain` test |
| INV-27 | A durable receipt follows the journal transaction; retries reuse the UUID | Receipts after COMMIT; spool reuses the UUID; spool loss is journaled before its markers and expired records leave the spool | Crash matrix (100 injections: 0 acknowledged lost, 0 duplicate facts); companion `spool_loss` test |
| INV-29 | One writer; replay preserves unresolved state and command receipts | Single writer thread; checkpoint + replay; baseline for M0 stores | Replay digests; migration evidence |
| Waits | A delayed positive before a clear cannot reopen attention; a late, earlier clear leaves no item open; a clear never resolves another generation; incomparable evidence never auto-clears | Episode partition by comparable clears; an emptied episode's item resolved as superseded (D-0007 §4) | `delayed-positive-wait`, `delayed-clear-wait`, `wait-generations`, `waiting` |
| Session turn | A session with no active turn shows its causally latest settled turn's state, never the first-arrived | `latest_settled_state`; the session's turn state is in semantic equality | `latest-turn-outcome`; `outcomes` permutations |
| Outbox | One intent per item, found by item: a migrated M0 intent keeps governing it; a live batch reports only intents still pending | `Index::attention_outbox`; batch filter on `PENDING` | `migrated_outbox` test; SQLite `a_live_batch_returns_only_…` |
| Atomicity | Projection, attention, outbox and cursor commit together | One transaction per batch; engine rebuilt from store on failure | Crash matrix (stores consistent after every injection); `tables == state` after every step in 1,040 SQLite runs |
| Purity | The reducer reads no ambient state | Module scan in `crates/state-engine/tests/purity.rs` | That test |
| Sanitization | Provider bodies never reach a persisted record | Capture allowlist; admission retains only the adapter's allowlisted payload | `evidence/M1/sanitization/` (store and spool scans), `sensitive-payload`, SQLite `sensitive_bodies_…`, relay `bodies_and_paths_…` |
